02 / WORKING PRINCIPLES

把愿景落到三条做事规范。

保存好原料，提供合适的使用入口，再通过真实工作持续积累。

01 / WRITE

规范的 Markdown

先把事实写清楚。内容简洁、结构明确、来源可追溯，每项事实有自己的维护位置。

02 / USE

高效的 CLI

让 Agent 先定位，再按需读取和操作。优先成熟能力，CLI、脚本与代码各用所长。

03 / BUILD

算力变成长期资产

围绕真实问题安排研究、编码与评审，以可复用产物和验收衡量模型额度的价值。

分域自持·统一发现·按需读取·结果回源

03 / NOTES FROM PRACTICE

走过的弯路，也留下来。

项目的价值也来自做事过程：记住问题如何发生，以及下次如何做得更好。

01上下文越堆越重

入口塞进历史、手册和完整档案，一次提问就承担了过多的阅读成本。

入口保持小，详细知识保持全；按任务加载，用局部更新保留经验。

02框架长得比需求快

更多命令、更多版本和更复杂的编排，很容易挤掉真正的用户问题。

先复用成熟能力；有证据的缺口才新增实现，以实际收益决定下一步。

03验收要走真实路径

格式检查和质量门禁解决一部分问题，实际使用与恢复仍需要自己的证据。

验证真实用户路径，记录结果、适用条件与尚未确认的部分。

04自动化需要明确边界

超时可能意味着结果未知，盲目重试会造成重复执行或重复产出。

保留任务证据，先核对原执行结果，再在授权范围内恢复。
